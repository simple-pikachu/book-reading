## 1. 索引组织表（IOT）与主键（约 p.91–95）

**要点**：

- InnoDB 表是**索引组织表**：数据即按主键排序的 B+ 树叶子节点。
- 主键选择规则：取表上第一个**非空唯一索引**（`NOT NULL` + `UNIQUE`）作为聚集索引；若没有，InnoDB 自动生成 **6 字节**隐藏主键（内部指针）。
- 可通过伪列 `_rowid` 访问该隐藏主键（仅当表确由引擎生成时）。

**原文**：

> InnoDB 存储引擎表是索引组织表，即数据按照主键的顺序存放。每个表都有主键，如果没有显式定义，引擎会选择第一个非空唯一索引；若仍不存在，则创建 6 字节的 RowID 作为主键。

> 用户可以通过伪列 `_rowid` 来访问这个 RowID，但前提是该表确实使用了 InnoDB 生成的主键。

**8.0.34 新写法**：

```sql
-- 显式短主键仍是最佳实践；勿依赖隐藏 RowID
CREATE TABLE t_iot (
  id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
  uk_code VARCHAR(32) NOT NULL,
  UNIQUE KEY uk_code (uk_code)
) ENGINE=InnoDB;

SELECT TABLE_NAME, SPACE, ROW_FORMAT
FROM information_schema.INNODB_TABLES
WHERE NAME LIKE '%t_iot%';
```

## 2. 表空间、段、区、页（约 p.96–110）

**要点**：

| 层级 | 含义（书中口径） |
|------|------------------|
| 表空间 | 逻辑容器；共享或独立 `.ibd` |
| 段（segment） | 索引的叶子/非叶子等 |
| 区（extent） | 连续页组成，**默认 1MB** |
| 页（page） | 最小磁盘单位，**默认 16KB** |

- 碎片页：不足一整区时先分配最多 **32 个**零散页。
- `innodb_page_size`：可设 4K/8K/16K/32K/64K（实例级，创建时定）。

**原文**：

> 区（extent）是由连续的页组成的空间，在任何情况下每个区的大小总是为 1MB。默认页大小为 16KB，故一个区中有 64 个连续页。为高效利用空间，InnoDB 会先申请最多 32 个碎片页。

**8.0.34 新写法**：

```sql
SHOW VARIABLES LIKE 'innodb_page_size';
SHOW VARIABLES LIKE 'innodb_file_per_table';  -- 8.0 默认 ON

-- 表空间信息（取代书中部分 INNODB_SYS_* 视角）
SELECT NAME, SPACE_TYPE, SPACE, FILE_SIZE, ALLOCATED_SIZE
FROM information_schema.INNODB_TABLESPACES
LIMIT 20;
```

## 3. 行记录格式：Compact / Redundant / Dynamic / Compressed（约 p.111–130）

**要点**：

- 书中主讲 **Compact** 与 **Redundant**；隐藏列：**事务 ID 6 字节**、**回滚指针 7 字节**。
- **行溢出**：大 VARCHAR/BLOB 等可能存到溢出页，行内留 20 字节指针（Compact 叙事）。
- VARCHAR 最大长度受行格式、页大小、字符集约束；单列不宜盲目拉满。
- **Antelope**：Compact + Redundant；**Barracuda**：新增 **Compressed / Dynamic**（大前缀索引、更好溢出）。
- `CHAR` 按**字符长度**定义，多字节字符集下实际字节可变。

**原文**：

> Compact 行格式对变长字段有较好支持。每行记录除用户列外，还有隐藏的事务 ID（6 字节）和回滚指针（7 字节）。当行数据过大无法在页内完整存放时，发生行溢出。

> 文件格式 Antelope 包含 Compact 与 Redundant；Barracuda 引入 Compressed 与 Dynamic。可通过 `SHOW VARIABLES LIKE 'innodb_file_format'` 查看当前文件格式。

**8.0.34 新写法**：

```sql
-- innodb_file_format / innodb_large_prefix 已移除；勿再查询或配置
SHOW VARIABLES LIKE 'innodb_default_row_format';  -- 默认 dynamic
SHOW VARIABLES LIKE 'innodb_file_format';           -- 8.0 应为空/不存在

CREATE TABLE t_row (
  id INT PRIMARY KEY,
  c CHAR(10),
  v VARCHAR(500),
  b BLOB
) ENGINE=InnoDB
  ROW_FORMAT=DYNAMIC
  DEFAULT CHARSET=utf8mb4
  COLLATE=utf8mb4_0900_ai_ci;

SELECT NAME, ROW_FORMAT, ZIP_PAGE_SIZE
FROM information_schema.INNODB_TABLES
WHERE NAME LIKE '%/t_row';
```

## 4. 约束与 sql_mode（约 p.131–145）

**要点**：

- `sql_mode` 含 `STRICT_TRANS_TABLES` 时，非法值对事务表会报错而非悄悄截断/改写。
- 外键动作：`CASCADE` / `SET NULL` / `NO ACTION` / `RESTRICT`；InnoDB 对外键做**即时检查**（非延迟到 COMMIT）。
- 视图可带 `WITH CHECK OPTION`（`CASCADED` / `LOCAL`），限制通过视图的写入。
- **物化视图**：书对比 Oracle；MySQL **无原生物化视图**，需用表 + 定时/触发器模拟。

**原文**：

> 在严格模式下（如 STRICT_TRANS_TABLES），插入非法值会报错。外键约束在语句执行时立即检查。MySQL 本身不支持物化视图，而 Oracle 等数据库提供该特性。

**8.0.34 新写法**：

```sql
SELECT @@sql_mode;  -- 8.0 默认已含严格相关模式

CREATE TABLE parent (
  id INT PRIMARY KEY
) ENGINE=InnoDB;

CREATE TABLE child (
  id INT PRIMARY KEY,
  pid INT,
  CONSTRAINT fk_child_parent
    FOREIGN KEY (pid) REFERENCES parent(id)
    ON DELETE CASCADE ON UPDATE RESTRICT
) ENGINE=InnoDB;

CREATE VIEW v_child AS
SELECT * FROM child WHERE id < 100
WITH CASCADED CHECK OPTION;
```

## 5. 分区表（约 p.146–182）

**要点**：

- 分区由 **MySQL Server** 实现，**不是**存储引擎层特性；InnoDB 等引擎只负责各分区底层存储。
- 常见为**水平分区**（按行划分）；索引多为**局部分区索引**（各分区各有一份索引）。
- **分区列必须是唯一索引（含主键）的组成部分**，否则无法建唯一约束跨全表。
- 书中用 `EXPLAIN PARTITIONS` 看分区裁剪；支持 **COLUMNS** 分区、**子分区**（HASH/KEY）。
- **NULL**：RANGE/LIST 等对 NULL 有专门落入规则（常进最左/指定分区）。
- **OLTP 慎用分区**：点查未必更快，管理/统计/连接成本上升；适合归档、按时间大范围扫描。
- `ALTER TABLE ... EXCHANGE PARTITION`：分区与普通表快速交换。

**原文**：

> MySQL 数据库的分区是在引擎层之上实现的水平分区。分区列必须是唯一索引的一部分。可以通过 `EXPLAIN PARTITIONS` 观察分区裁剪。对于 OLTP 应用，应谨慎使用分区。

**8.0.34 新写法**：

```sql
-- 仅 InnoDB（及 NDB）原生分区；MyISAM 分区表不能直接升级到 8.0
CREATE TABLE t_part (
  id BIGINT NOT NULL,
  created_at DATE NOT NULL,
  PRIMARY KEY (id, created_at)
) ENGINE=InnoDB
PARTITION BY RANGE COLUMNS(created_at) (
  PARTITION p2024 VALUES LESS THAN ('2025-01-01'),
  PARTITION p2025 VALUES LESS THAN ('2026-01-01'),
  PARTITION pmax  VALUES LESS THAN (MAXVALUE)
);

-- EXPLAIN 默认含分区信息，勿再写 EXPLAIN PARTITIONS
EXPLAIN SELECT * FROM t_part
WHERE created_at >= '2025-06-01' AND created_at < '2025-07-01';

CREATE TABLE t_part_ex LIKE t_part;
ALTER TABLE t_part_ex REMOVE PARTITIONING;

ALTER TABLE t_part EXCHANGE PARTITION p2024 WITH TABLE t_part_ex;
```

## 6. DDL 与元数据（8.0.34 对照小结）

**要点（书中 5.6 味 → 现行）**：

| 书中写法 | 8.0.34 |
|----------|--------|
| `innodb_file_format` / Antelope·Barracuda | **已移除**；默认 `ROW_FORMAT=DYNAMIC` |
| `innodb_large_prefix` | **已移除** |
| 默认字符集偏 `latin1`/`utf8`(mb3) | 默认 **`utf8mb4`** |
| DDL 与 `.frm` 崩溃语义复杂 | **Atomic DDL** |
| Online DDL 能力有限 | 扩展 + **`ALGORITHM=INSTANT`** |
| `INNODB_SYS_TABLES` | **`information_schema.INNODB_TABLES`** |

**8.0.34 新写法**：

```sql
SHOW VARIABLES LIKE 'character_set_server';
SHOW VARIABLES LIKE 'collation_server';

-- Instant DDL（支持时几乎只改数据字典）
ALTER TABLE t_iot ADD COLUMN note VARCHAR(32) NULL, ALGORITHM=INSTANT;

SELECT NAME, FLAG, N_COLS, SPACE, ROW_FORMAT
FROM information_schema.INNODB_TABLES
WHERE NAME LIKE '%/t_iot';
```

## 7. 本章小结

1. **索引组织表**：主键即数据顺序；无合适唯一索引则用 6 字节 RowID。  
2. **物理结构**：表空间 → 段 → 区(1MB) → 页(默认 16KB)。  
3. **行格式**：学 Compact 隐藏列与溢出；生产以 **DYNAMIC + utf8mb4** 为准。  
4. **约束/视图**：严格模式、即时外键、`WITH CHECK OPTION`；无原生物化视图。  
5. **分区**：Server 层水平分区；唯一索引须含分区列；OLTP 慎用；8.0 仅 InnoDB 原生分区。
