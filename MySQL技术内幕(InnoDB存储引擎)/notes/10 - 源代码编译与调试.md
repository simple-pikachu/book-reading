## 3. 获取 MySQL 8.0.34 源码

**要点**：

- 官方镜像 / GitHub：**[mysql/mysql-server](https://github.com/mysql/mysql-server)**
- 对应 tag：`mysql-8.0.34`（勿误用 `8.0` 分支浮动提交当「就是 8.0.34」）
- 也可用 Oracle 提供的源码包（`mysql-8.0.34.tar.gz`），注意许可证与 GSL 组件。

**8.0.34 新写法**：

```bash
git clone https://github.com/mysql/mysql-server.git
cd mysql-server
git checkout mysql-8.0.34
git describe --tags   # 确认落在 mysql-8.0.34
```

目录心智（概念性，名称随树微调）：

| 区域 | 大致位置（概念） | 读什么 |
|------|------------------|--------|
| Server 层 | `sql/` | 解析、优化、执行、事务协调、DDL 入口 |
| 数据字典 | `sql/dd/`、`sql/dd/` 相关 | 事务型 DD、表定义持久化 |
| InnoDB | `storage/innobase/` | 缓冲池、redo/undo、锁、B+ 树、purge |
| 原子 DDL / 提交路径 | server 事务与 binlog 协调 + InnoDB prepare/commit | 内部 XA、崩溃安全 |
| 复制 | `sql/rpl_*`、`sql/binlog*` | binlog、GTID、applier |

> 说明：上表是**概念地图**，不是稳定 API 承诺；以你 checkout 的树内实际路径为准。

## 4. CMake 现代编译流程概要

**要点**：

- 8.0 使用 **CMake** 生成构建文件；依赖 boost（历史上）、OpenSSL、ncurses、编译器工具链等（随平台变化，以官方 *Installing MySQL from Source* 为准）。
- Debug 构建：`-DCMAKE_BUILD_TYPE=Debug`，便于 gdb/lldb。
- 常见关闭项：不需要的存储引擎、测试套件，以缩短编译时间。

**8.0.34 新写法（示意，请对照 8.0.34 官方文档微调）**：

```bash
mkdir bld && cd bld
cmake .. \
  -DCMAKE_BUILD_TYPE=Debug \
  -DWITH_DEBUG=1 \
  -DDOWNLOAD_BOOST=1 \
  -DWITH_BOOST=../boost \
  -DCMAKE_INSTALL_PREFIX=/usr/local/mysql-8.0.34-debug

cmake --build . -j$(nproc)   # Windows 下用对应生成器与 -j
cmake --install .
```

Windows（书读者常见环境）：

- 使用 Visual Studio 生成器或官方文档推荐工具链。
- 路径、OpenSSL、Boost 的找包方式与 Linux 不同，**以 8.0.34 平台文档为准**，不要混用 5.1 章节命令。

初始化数据目录与启动调试实例：

```bash
mysqld --initialize-insecure --datadir=/path/to/data --basedir=/usr/local/mysql-8.0.34-debug
mysqld --datadir=/path/to/data --gdb   # 或外部 gdb 附加
```

## 5. 调试注意点（8.0.34）

**要点**：

1. **Debug 构建性能极差**：仅用于功能追踪，勿当压测对象。  
2. **数据字典**：表定义不再是「看 `.frm`」；调试 DDL 要跟着 DD 事务与 `mysql.ibd` 相关路径。  
3. **原子 DDL**：关注失败/崩溃时元数据回滚路径，避免用 5.1 的「文件残留」直觉解释 8.0。  
4. **redo 文件布局**：≥8.0.30 常见 `#innodb_redo/` 与 `innodb_redo_log_capacity`，与书中 `ib_logfile0/1` 叙事并存理解（旧实例升级路径另论）。  
5. **线程多**：page cleaner、purge、io threads 等；下断点注意别只停在「曾经的 Master Thread」心智。  
6. **测试**：`mysql-test-run`（MTR）仍是回归利器；改引擎代码后优先跑相关 suite。

**原文（方法论，版本已变）**：

> 通过调试器跟踪 InnoDB 存储引擎的源代码，可以深入理解诸如缓冲池、锁、事务提交等关键路径的实现。

**8.0.34 新写法**：

```text
建议断点「问题驱动」示例：
- 事务提交：binlog dump + InnoDB prepare/commit
- 一致性读：read view / undo 遍历
- 死锁：lock wait 图构建
- DDL：DD 事务提交与 InnoDB 表存储联动
```

```bash
gdb --args mysqld --datadir=... 
# break 在感兴趣的函数后 run
```
