## 1. 参数文件：动态与静态（约第 62–65 页）

**要点**：

- MySQL 可通过配置文件（如 `my.cnf` / `my.ini`）与命令行启动项设定参数。
- **动态参数**可在运行中 `SET` 修改；**静态参数**需写入配置并重启实例。
- 改参前先用 `SHOW VARIABLES` / `performance_schema` 确认当前值与是否可动态修改。

**原文**：

> MySQL 数据库中的参数可以分为动态（dynamic）参数和静态（static）参数。动态参数意味着可以在 MySQL 数据库实例运行中进行修改；静态参数说明在整个实例生命周期内都不得进行更改，要想更改必须重启实例。对于动态参数，可以通过 `SET` 命令进行修改，修改的作用域分为 session 与 global。

**8.0.34 新写法**：

```sql
-- 查看某参数是否可动态修改
SELECT VARIABLE_NAME, VARIABLE_SCOPE, IS_DYNAMIC
FROM performance_schema.variables_info
WHERE VARIABLE_NAME IN (
  'innodb_buffer_pool_size',
  'max_connections',
  'datadir',
  'innodb_redo_log_capacity'
);

SET GLOBAL max_connections = 500;                 -- 动态示例
SET PERSIST max_connections = 500;                -- 写入 mysqld-auto.cnf，重启仍在
-- SET PERSIST_ONLY ...                           -- 仅持久化，当前进程暂不改

SHOW VARIABLES LIKE 'innodb_buffer_pool_size';
```

```ini
[mysqld]
max_connections=500
# 静态项（如 datadir）只能写配置后重启
```

## 2. 错误日志（约第 65–67 页）

**要点**：

- 错误日志记录启动/关闭、严重错误、部分告警；排障首看之处。
- 8.0 用 `log_error` 定位文件；详细程度用 **`log_error_verbosity`**（替代旧 `log_warnings` 叙事）。

**原文**：

> 错误日志文件对 MySQL 的启动、运行、关闭过程进行了记录。当数据库发生故障时，应首先查看该文件以便定位问题。错误日志文件的路径由参数 `log_error` 指定。在默认情况下，错误日志文件的文件名是主机名 `.err`。

**8.0.34 新写法**：

```sql
SHOW VARIABLES LIKE 'log_error';
SHOW VARIABLES LIKE 'log_error_verbosity';
-- 1=仅 error；2=error+warning；3=error+warning+note（常见默认）
SET PERSIST log_error_verbosity = 2;
```

```ini
[mysqld]
log_error=/var/log/mysql/error.log
log_error_verbosity=2
# 勿再依赖已移除/过时的 log_warnings 作为主开关
```

## 3. 慢查询日志（约第 67–72 页）

**要点**：

- `long_query_time` 单位为秒（可为小数）；判定是**大于**该阈值，不是大于等于。
- 可记录未使用索引的语句；也可用节流参数限制「未用索引」类刷屏。
- 书中曾建议把 `mysql.slow_log` 从 CSV 改为 MyISAM——**8.0.34 不要再改成 MyISAM**；优先文件慢日志或 Performance Schema。

**原文**：

> 慢查询日志由参数 `long_query_time` 控制，默认值为 10，代表运行时间大于 10 秒的查询会记录到慢查询日志文件中。需要特别注意的是：该阈值的含义是运行时间**大于** `long_query_time` 的查询，而不是大于等于。

> 参数 `log_queries_not_using_indexes` 可将没有使用索引的查询记录到慢查询日志。参数 `log_throttle_queries_not_using_indexes` 表示一分钟内允许记录到慢查询日志的、未使用索引的 SQL 语句次数，用于避免大量此类语句淹没日志。

> 慢查询日志也可以记录到表中。默认使用 CSV 引擎的 `mysql.slow_log` 表。由于 CSV 引擎的限制，用户可将 `slow_log` 表的引擎修改为 MyISAM，以便于查询与维护。

**8.0.34 新写法**：

```sql
SHOW VARIABLES LIKE 'slow_query_log';
SHOW VARIABLES LIKE 'slow_query_log_file';
SHOW VARIABLES LIKE 'long_query_time';
SHOW VARIABLES LIKE 'log_queries_not_using_indexes';
SHOW VARIABLES LIKE 'log_throttle_queries_not_using_indexes';
SHOW VARIABLES LIKE 'log_output';          -- FILE / TABLE / NONE

SET PERSIST slow_query_log = ON;
SET PERSIST long_query_time = 1;          -- >1 秒才记；1.000000 整秒边界按「大于」理解
SET PERSIST log_queries_not_using_indexes = ON;
SET PERSIST log_throttle_queries_not_using_indexes = 10;
SET PERSIST log_output = 'FILE';          -- 推荐 FILE；不要把 mysql.slow_log 改成 MyISAM

-- 更推荐用 Performance Schema 做语句摘要（无需改系统表引擎）
SELECT schema_name, digest_text, count_star, avg_timer_wait
FROM performance_schema.events_statements_summary_by_digest
ORDER BY avg_timer_wait DESC
LIMIT 20;
```

```ini
[mysqld]
slow_query_log=ON
slow_query_log_file=/var/log/mysql/mysql-slow.log
long_query_time=1
log_queries_not_using_indexes=ON
log_throttle_queries_not_using_indexes=10
log_output=FILE
```

## 4. 二进制日志（约第 72–80 页）

**要点**：

- binlog 记录对数据的**更改**类操作；**不含**单纯的 `SELECT` / `SHOW`。
- `binlog_cache_size` 是**会话级**缓存，用于事务中尚未提交的 binlog 事件。
- `sync_binlog=1` 提高 binlog 耐久性，但与 InnoDB 提交之间仍可能存在「裂缝」窗口，需结合 `innodb_flush_log_at_trx_commit` 等一起设计。
- 格式：`STATEMENT` / `ROW` / `MIXED`；**8.0.34 默认 `ROW`**。

**原文**：

> 二进制日志（binary log）记录了所有对 MySQL 数据库的修改操作，但不包括 `SELECT` 和 `SHOW` 这类操作，因为这类操作对数据本身并没有修改。

> 参数 `binlog_cache_size` 用于控制二进制日志的缓存大小，它是**会话级**参数：当事务尚未提交时，日志先写入缓存；提交后再写入二进制日志文件。不要把它理解成全局共享的唯一大缓存。

> 即使设置 `sync_binlog=1`，在与 InnoDB 存储引擎配合时，仍可能存在 binlog 已落盘而 InnoDB 事务尚未完成提交（或相反）的「裂缝」——崩溃恢复与复制一致性需要同时考虑 binlog 与 redo 的刷盘策略。

> 参数 `binlog_format` 可设置为 `STATEMENT`、`ROW`、`MIXED`。基于语句的复制记录 SQL 文本；基于行的复制记录行级变更；混合模式由 MySQL 自行在两者间选择。

**8.0.34 新写法**：

```sql
SHOW VARIABLES LIKE 'log_bin';
SHOW VARIABLES LIKE 'binlog_format';          -- 默认 ROW
SHOW VARIABLES LIKE 'binlog_cache_size';      -- 会话级
SHOW VARIABLES LIKE 'max_binlog_cache_size';
SHOW VARIABLES LIKE 'sync_binlog';
SHOW VARIABLES LIKE 'innodb_flush_log_at_trx_commit';
SHOW VARIABLES LIKE 'gtid_mode';
SHOW BINARY LOGS;
SHOW MASTER STATUS;   -- 8.0.22+ 也可用 SHOW BINARY LOG STATUS
```

```ini
[mysqld]
server_id=1
log_bin=mysql-bin
binlog_format=ROW
sync_binlog=1
innodb_flush_log_at_trx_commit=1
binlog_cache_size=1M
gtid_mode=ON
enforce_gtid_consistency=ON
```

```sql
-- 耐久性常见「双 1」组合（吞吐换安全）
SET PERSIST sync_binlog = 1;
SET PERSIST innodb_flush_log_at_trx_commit = 1;
```

## 5. 表结构文件与 .frm（约第 80–82 页）

**要点**：

- 书中强调无论何种引擎都有 `.frm` 存表定义——这在 **MySQL 8.0 已过时**。
- 8.0.34：无 `.frm`；表定义在**事务型数据字典**（如 `mysql.ibd`）；`sync_frm` 已移除。

**原文**：

> 但不论表采用何种存储引擎，MySQL 都有一个以 frm 为后缀名的文件，这个文件记录了该表的表结构定义。

**8.0.34 新写法**：

```sql
SHOW VARIABLES LIKE 'datadir';
-- 数据目录中不应再把 .frm 当作元数据真相源
-- 亦无 sync_frm 参数

SELECT TABLE_SCHEMA, TABLE_NAME, TABLE_TYPE, ENGINE
FROM information_schema.TABLES
WHERE TABLE_SCHEMA = 'appdb';

SHOW CREATE TABLE appdb.orders\G

-- 字典相关（只读了解）
SHOW VARIABLES LIKE 'datadir';
-- 常见：datadir/mysql/mysql.ibd 承载数据字典
```

```bash
# 8.0.34 预期：表目录下主要是 *.ibd（file-per-table），没有 *.frm
ls "$DATADIR/appdb"
```

## 6. 独立表空间与 innodb_file_per_table（约第 82–85 页）

**要点**：

- `innodb_file_per_table=ON` 时，每表（或每分区）有独立 `.ibd`。
- 独立表空间主要存放**数据、索引以及 insert buffer bitmap** 等；Insert/Change Buffer 的 B+ 树本体仍在共享/系统相关区域（见第 2 章）。

**原文**：

> 参数 `innodb_file_per_table` 用于开启或关闭 InnoDB 的独立表空间属性。若开启，则每张表的数据与索引存放在单独的 `.ibd` 文件中。需要注意：独立表空间文件中仅存放该表的数据、索引和插入缓冲的 bitmap 等信息，Insert Buffer 的 B+ 树仍在共享表空间中。

**8.0.34 新写法**：

```sql
SHOW VARIABLES LIKE 'innodb_file_per_table';   -- 8.0 默认 ON
SET PERSIST innodb_file_per_table = ON;

CREATE TABLE appdb.t1 (
  id BIGINT PRIMARY KEY,
  c1 VARCHAR(100)
) ENGINE=InnoDB;

-- 确认文件（需 FILE 权限或 OS 侧查看）
SELECT TABLE_NAME, SPACE, NAME, FILE_SIZE
FROM information_schema.INNODB_TABLESPACES
WHERE NAME LIKE 'appdb/%';
```

```ini
[mysqld]
innodb_file_per_table=ON
```

## 7. 重做日志文件（约第 85–90 页）

**要点**：

- 书中：`ib_logfile0`、`ib_logfile1` 等；至少 2 个 redo 文件；循环写。
- redo 是**物理日志**（页的变更），binlog 是**逻辑日志**（服务器层语句/行事件）；层次与用途不同。
- `innodb_flush_log_at_trx_commit=1`：每事务提交都将 redo 刷到磁盘，耐久性最强。
- **8.0.34（≥8.0.30）**：用 **`innodb_redo_log_capacity`** 管理容量；文件位于 `#innodb_redo` 目录；`innodb_log_file_size` × `innodb_log_files_in_group` 已弃用勿再当主配置。
- undo 使用**独立 undo tablespace**，可用 `CREATE UNDO TABLESPACE`。

**原文**：

> 默认情况下，在 InnoDB 存储引擎的数据目录下会有两个名为 `ib_logfile0` 和 `ib_logfile1` 的文件，即 redo 日志文件。InnoDB 存储引擎至少应有两个重做日志文件；若只有一个，则在日志切换等场景下无法正常工作。重做日志采用循环写的方式：写到最后一个文件末尾后回到第一个文件开头继续写（受 checkpoint 推进约束）。

> 重做日志是物理日志，记录的是对每个页的修改；二进制日志是逻辑日志，记录的是相应的 SQL 语句（或行变更事件）。二者层次不同：binlog 在 MySQL Server 层，redo 在 InnoDB 存储引擎层。

> 参数 `innodb_flush_log_at_trx_commit` 用于控制提交时 redo 的刷盘策略。当设置为 1 时，表示事务提交时必须将 redo 日志同步到磁盘，这可以保证 ACID 中的持久性（D）；设置为 0 或 2 则在性能与耐久性之间折中，崩溃时可能丢失部分已提交事务。

**8.0.34 新写法**：

```sql
SHOW VARIABLES LIKE 'innodb_redo_log_capacity';
SHOW VARIABLES LIKE 'innodb_log_file_size';         -- 弃用兼容
SHOW VARIABLES LIKE 'innodb_log_files_in_group';    -- 弃用兼容
SHOW VARIABLES LIKE 'innodb_flush_log_at_trx_commit';
SHOW VARIABLES LIKE 'innodb_undo_directory';
SHOW VARIABLES LIKE 'datadir';

SET PERSIST innodb_redo_log_capacity = 2*1024*1024*1024;  -- 2G，可按负载调
SET PERSIST innodb_flush_log_at_trx_commit = 1;
```

```ini
[mysqld]
# 书中/5.6 味（过时，勿再作为主配置）
# innodb_log_file_size=512M
# innodb_log_files_in_group=2

# 8.0.34 推荐
innodb_redo_log_capacity=2G
innodb_flush_log_at_trx_commit=1
```

```bash
# redo 文件目录（相对 datadir）
ls "$DATADIR/#innodb_redo"
```

```sql
-- 独立 undo 表空间（8.0）
CREATE UNDO TABLESPACE undo_003 ADD DATAFILE 'undo_003.ibu';
ALTER UNDO TABLESPACE undo_003 SET ACTIVE;
-- ALTER UNDO TABLESPACE undo_003 SET INACTIVE;
-- DROP UNDO TABLESPACE undo_003;

SELECT NAME, STATE, SPACE_TYPE
FROM information_schema.INNODB_TABLESPACES
WHERE SPACE_TYPE = 'Undo' OR NAME LIKE '%undo%';
```

## 8. 本章文件地图（书中 vs 8.0.34）

| 类型 | 书中常见 | MySQL 8.0.34 |
|------|----------|--------------|
| 表定义 | `*.frm` | **数据字典**（无 frm / 无 sync_frm） |
| 表数据 | `*.ibd`（file-per-table） | 仍常用；默认 `innodb_file_per_table=ON` |
| redo | `ib_logfile0/1` + size×files | **`innodb_redo_log_capacity`** + `#innodb_redo` |
| undo | 常与系统表空间混谈 | **独立 undo tablespace** / `CREATE UNDO TABLESPACE` |
| 错误日志 | `log_error` | + **`log_error_verbosity`** |
| 慢日志 | 改 `slow_log`→MyISAM | **保持 FILE / P_S**；不要改 MyISAM |
| binlog | STATEMENT/ROW/MIXED | **默认 ROW**；配合 GTID |

```sql
-- 一键核对
SHOW VARIABLES LIKE 'innodb_file_per_table';
SHOW VARIABLES LIKE 'innodb_redo_log_capacity';
SHOW VARIABLES LIKE 'innodb_flush_log_at_trx_commit';
SHOW VARIABLES LIKE 'binlog_format';
SHOW VARIABLES LIKE 'log_error_verbosity';
SHOW VARIABLES LIKE 'slow_query_log';
SHOW VARIABLES LIKE 'long_query_time';
```
