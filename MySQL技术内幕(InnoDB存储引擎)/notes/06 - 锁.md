## 1. latch 与 lock（约 p.249–252）

**要点**：

- **latch**（闩锁）：轻量锁，保护内存数据结构（如页、哈希），通常持有时间极短；分 mutex 与 rwlock。
- **lock**：事务锁，保护数据库内容（行、表、间隙），持有到事务结束（或显式释放规则）。
- 可用 `SHOW ENGINE INNODB MUTEX` 观察 mutex/rwlock 争用（书中监控入口）。

**原文**：

> latch 一般称为闩锁（轻量级的锁），因为其要求锁定的时间必须非常短。若持续的时间长，则应用的性能会非常差。在 InnoDB 存储引擎中，latch 又可以分为 mutex（互斥量）和 rwlock（读写锁）。其目的是用来保证并发线程操作临界资源的正确性，并且通常没有死锁检测的机制。

> 对于 InnoDB 存储引擎中的 latch，可以通过命令 SHOW ENGINE INNODB MUTEX 来进行查看。

**8.0.34 新写法**：

```sql
SHOW ENGINE INNODB MUTEX;

-- 日常更常结合 Performance Schema 等待事件
SELECT EVENT_NAME, COUNT_STAR, SUM_TIMER_WAIT
FROM performance_schema.events_waits_summary_global_by_event_name
WHERE EVENT_NAME LIKE 'wait/synch/mutex/innodb/%'
ORDER BY SUM_TIMER_WAIT DESC
LIMIT 15;
```

## 2. 查看锁信息（书中写法 → 8.0.34）（约 p.253–256）

**要点**：

- 书中用 **`INFORMATION_SCHEMA.INNODB_TRX`**、**`INNODB_LOCKS`**、**`INNODB_LOCK_WAITS`** 分析阻塞链。
- 8.0 起 `INNODB_LOCKS` / `INNODB_LOCK_WAITS` **已移除**，改走 Performance Schema / sys。

**原文**：

> 相对于 latch 的查看，lock 信息就显得直观多了。用户可以通过命令 SHOW ENGINE INNODB STATUS 及 information_schema 架构下的表 INNODB_TRX、INNODB_LOCKS、INNODB_LOCK_WAITS 来观察锁的信息。

> 从 InnoDB 1.0 开始，在 INFORMATION_SCHEMA 架构下添加了表 INNODB_TRX、INNODB_LOCKS、INNODB_LOCK_WAITS。通过这三张表，用户可以更简单地监控当前事务并分析可能存在的锁问题。

**8.0.34 新写法**：

```sql
-- 事务仍可用
SELECT trx_id, trx_state, trx_started, trx_query
FROM information_schema.INNODB_TRX;

-- 行/表锁：Performance Schema
SELECT ENGINE_TRANSACTION_ID, OBJECT_SCHEMA, OBJECT_NAME,
       INDEX_NAME, LOCK_TYPE, LOCK_MODE, LOCK_STATUS, LOCK_DATA
FROM performance_schema.data_locks
LIMIT 50;

SELECT * FROM performance_schema.data_lock_waits LIMIT 50;

-- 可读性更好的阻塞视图
SELECT * FROM sys.innodb_lock_waits\G
```

## 3. 锁类型与一致性非锁定读（约 p.257–265）

**要点**：

- **S（共享）** / **X（排他）**；**意向锁** IS / IX：表级提示，便于快速判断表锁兼容性。
- **一致性非锁定读**：普通 `SELECT` 通过 **MVCC** 读历史版本，不加锁（默认隔离级别下）。
- **快照**：
  - **READ COMMITTED**：语句级快照，每句可能看到新提交。
  - **REPEATABLE READ**（InnoDB 默认）：事务级快照，同事务重复读一致（配合 Next-Key 抑制幻读）。

**原文**：

> 一致性的非锁定读（consistent nonlocking read）是指 InnoDB 存储引擎通过行多版本控制（multi versioning）的方式来读取当前执行时间数据库中行的数据。如果读取的行正在执行 DELETE 或 UPDATE 操作，这时读取操作不会因此去等待行上锁的释放。相反地，InnoDB 存储引擎会去读取行的一个快照数据。

> 在事务隔离级别 READ COMMITTED 和 REPEATABLE READ（InnoDB 存储引擎的默认事务隔离级别）下，InnoDB 存储引擎使用非锁定的一致性读。然而，对于快照数据的定义却不相同。在 READ COMMITTED 事务隔离级别下，对于快照数据，非一致性读总是读取被锁定行的最新一份快照数据。而在 REPEATABLE READ 事务隔离级别下，对于快照数据，非一致性读总是读取事务开始时的行数据版本。

**8.0.34 新写法**：

```sql
-- tx_isolation 已弃用/移除路径 → 用 transaction_isolation
SELECT @@transaction_isolation;
SET SESSION transaction_isolation = 'REPEATABLE-READ';
SET SESSION transaction_isolation = 'READ-COMMITTED';

START TRANSACTION;
SELECT * FROM t_idx WHERE id = 1;  -- 一致性非锁定读
COMMIT;
```

## 4. 锁定读：FOR UPDATE / SHARE（约 p.266–268）

**要点**：

- `SELECT ... FOR UPDATE`：对扫描到的行加 **X 锁**（及必要间隙锁）。
- `SELECT ... LOCK IN SHARE MODE`：加 **S 锁**（书中语法）。
- 用于「读后更新」防止丢失更新；注意锁范围与隔离级别。

**原文**：

> InnoDB 存储引擎对于 SELECT 语句支持两种一致性的锁定读（locking read）操作：SELECT…FOR UPDATE；SELECT…LOCK IN SHARE MODE。

> SELECT…FOR UPDATE 对读取的行记录加一个 X 锁，其他事务不能对已锁定的行加上任何锁。SELECT…LOCK IN SHARE MODE 对读取的行记录加一个 S 锁，其他事务可以向被锁定的行加 S 锁，但是如果加 X 锁，则会被阻塞。

**8.0.34 新写法**：

```sql
START TRANSACTION;
-- 8.0 推荐 FOR SHARE（LOCK IN SHARE MODE 仍兼容）
SELECT * FROM t_idx WHERE id = 1 FOR SHARE;
SELECT * FROM t_idx WHERE id = 2 FOR UPDATE;

-- 跳过已锁行 / 不等待
SELECT * FROM t_idx WHERE a = 10 FOR UPDATE SKIP LOCKED;
SELECT * FROM t_idx WHERE a = 11 FOR UPDATE NOWAIT;
COMMIT;
```

## 5. 自增锁：AUTO-INC Locking（约 p.269–272）

**要点**：

- 传统 **AUTO-INC 表级锁**：插入取号时锁表，保证自增连续，但并发差。
- MySQL **5.1.22+**：`innodb_autoinc_lock_mode` 提供更轻量模式（0 传统 / 1 连续 / 2 交错），减少表级 AUTO-INC 锁持有。
- 批量 `INSERT ... SELECT` 等场景模式差异影响最大。

**原文**：

> AUTO-INC Locking 是一种特殊的表级锁。从 MySQL 5.1.22 起，InnoDB 提供了轻量级的自增长实现，由参数 `innodb_autoinc_lock_mode` 控制。

**8.0.34 新写法**：

```sql
SHOW VARIABLES LIKE 'innodb_autoinc_lock_mode';
-- 常见：1（连续）或 2（交错，binlog_format=ROW 下更利于并发）

SHOW VARIABLES LIKE 'auto_increment_increment';
SHOW VARIABLES LIKE 'auto_increment_offset';
```

## 6. Record / Gap / Next-Key Lock（约 p.273–278）

**要点**：

| 算法 | 锁定对象 |
|------|----------|
| **Record Lock** | 单行索引记录 |
| **Gap Lock** | 记录之间的间隙，阻止插入 |
| **Next-Key Lock** | Record + 前面的 Gap（默认 RR 下范围扫描常用） |

- 在**唯一索引等值查询且记录存在**时，InnoDB 常将 Next-Key **降级为 Record Lock**，无需间隙锁。
- Gap / Next-Key 是抑制**幻读**的关键机制。

**原文**：

> InnoDB 有三种行锁算法：Record Lock、Gap Lock 与 Next-Key Lock。Next-Key Lock 是 Record Lock 与 Gap Lock 的结合。当查询的索引是唯一索引且精确匹配到记录时，Next-Key Lock 会降级为 Record Lock。

**8.0.34 新写法**：

```sql
SET SESSION transaction_isolation = 'REPEATABLE-READ';
START TRANSACTION;
-- 唯一键命中：多为 Record Lock；范围扫描：Next-Key / Gap
SELECT * FROM t_idx WHERE id = 1 FOR UPDATE;
SELECT * FROM t_idx WHERE a BETWEEN 1 AND 10 FOR UPDATE;

SELECT INDEX_NAME, LOCK_TYPE, LOCK_MODE, LOCK_DATA
FROM performance_schema.data_locks
WHERE OBJECT_NAME = 't_idx';
COMMIT;
```

## 7. 隔离问题、超时与死锁（约 p.279–284）

**要点**：

- 现象：**脏读**、**不可重复读**、**幻读**、**丢失更新**。
- InnoDB 默认 RR + MVCC + Next-Key，通常可避免脏读/不可重复读/幻读（在默认协议下）。
- **`innodb_lock_wait_timeout`**：锁等待超时（默认 50s），超时抛错，**不**回滚整个事务（仅当前语句失败，视 sql_mode/客户端处理）。
- **死锁**：用 **wait-for graph** 检测；发现后**回滚**代价较小的一方；应用需重试。
- InnoDB **无锁升级**：行锁用**位图按页**管理，不会因行数多自动升为表锁（对比部分数据库）。

**原文**：

> 锁等待超时由 `innodb_lock_wait_timeout` 控制。死锁通过等待图（wait-for graph）检测，检测到后会回滚其中一个事务。InnoDB 存储引擎不会进行锁升级，行锁通过位图按页管理。

**8.0.34 新写法**：

```sql
SHOW VARIABLES LIKE 'innodb_lock_wait_timeout';
SHOW VARIABLES LIKE 'innodb_deadlock_detect';  -- ON：开启死锁检测

SET SESSION innodb_lock_wait_timeout = 10;

-- 死锁后可在错误日志 / SHOW ENGINE INNODB STATUS 的 LATEST DETECTED DEADLOCK 查看
SHOW ENGINE INNODB STATUS\G
```

## 8. MySQL 8.0.34 锁相关变更小结

| 书中 / 旧写法 | 8.0.34 |
|---------------|--------|
| `INNODB_LOCKS` / `INNODB_LOCK_WAITS` | `performance_schema.data_locks` / `data_lock_waits`；`sys.innodb_lock_waits` |
| `tx_isolation` | **`transaction_isolation`** |
| `LOCK IN SHARE MODE` | 推荐 **`FOR SHARE`**；另有 **`SKIP LOCKED` / `NOWAIT`** |
| 锁系统全局结构 | **8.0.21+** 锁系统分片，降低锁管理器争用 |
| 死锁检测 | **`innodb_deadlock_detect`** 可关（高并发下偶用应用超时替代，慎用） |

**8.0.34 新写法**：

```sql
SELECT @@transaction_isolation, @@innodb_lock_wait_timeout, @@innodb_deadlock_detect;

SELECT requesting_engine_transaction_id AS waiting_trx,
       blocking_engine_transaction_id  AS blocking_trx
FROM performance_schema.data_lock_waits;
```

## 9. 本章小结

1. **latch ≠ lock**：前者护内存结构，后者护事务数据。  
2. **锁可见性**：8.0 用 `data_locks` / `data_lock_waits` / `sys.innodb_lock_waits`。  
3. **MVCC 非锁定读** vs **FOR UPDATE / FOR SHARE**；RC 与 RR 快照粒度不同。  
4. **AUTO-INC**：`innodb_autoinc_lock_mode` 决定并发与连续性权衡。  
5. **Record / Gap / Next-Key**：唯一等值可降级 Record；间隙锁防幻读。  
6. **死锁会回滚一方**；InnoDB **无**行锁升级到表锁。
