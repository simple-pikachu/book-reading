## 1. B+ 树索引基础（约 p.183–195）

**要点**：

- B+ 树中的 **B** 代表 **balance**（平衡），不是 binary。
- 索引定位到**页**后，再在页内做内存查找（如二分）；磁盘 I/O 以页为单位。
- 树高度通常 2–4；高度决定最坏随机读页次数，对大表性能至关重要。

**原文**：

> B+ 树中的 B 代表平衡（balance），而不是二叉（binary）。通过索引找到的是页，之后再在内存中进行查找。B+ 树的高度一般在 2～4 层，这意味着查找某一键值最多只需 2～4 次 I/O。

**8.0.34 新写法**：

```sql
-- 用 TREE 格式看访问路径；ANALYZE 看真实耗时与行数
EXPLAIN FORMAT=TREE
SELECT * FROM t_iot WHERE id = 1;

EXPLAIN ANALYZE
SELECT * FROM t_iot WHERE uk_code = 'A001';
```

## 2. 聚集索引与辅助索引（约 p.196–205）

**要点**：

- **聚集索引**：叶子节点即完整行；一张表只有一棵聚集索引树（主键）。
- **辅助（二级）索引**：叶子节点存放**书签 = 主键值**，再回表到聚集索引取行。
- 主键宜短、稳定：辅助索引会重复存储主键，过长主键放大二级索引体积与 I/O。

**原文**：

> 聚集索引按照主键构造一棵 B+ 树，叶子节点存放整行记录。辅助索引叶子节点包含主键值作为书签；通过书签再找到完整行数据。

**8.0.34 新写法**：

```sql
CREATE TABLE t_idx (
  id BIGINT UNSIGNED NOT NULL PRIMARY KEY,
  a INT NOT NULL,
  b INT NOT NULL,
  c VARCHAR(64) NOT NULL,
  KEY idx_ab (a, b),
  KEY idx_c (c)
) ENGINE=InnoDB;

-- 回表 vs 覆盖：只查索引列可避免回表
EXPLAIN FORMAT=TREE
SELECT a, b FROM t_idx WHERE a = 10 AND b > 5;
```

## 3. Cardinality 与统计信息（约 p.206–212）

**要点**：

- **Cardinality**：索引列不重复值的估计；优化器选索引的重要依据。
- `SHOW INDEX` 中的 Cardinality 可能过时；用 **`ANALYZE TABLE`** 更新。
- InnoDB 对页采样估算，非精确 COUNT DISTINCT。

**原文**：

> Cardinality 值表示索引中不重复记录的估计数量。优化器会根据 Cardinality 选择是否使用该索引。可通过 `ANALYZE TABLE` 重新计算。

**8.0.34 新写法**：

```sql
ANALYZE TABLE t_idx;

SHOW INDEX FROM t_idx;

-- 直方图（5.7+/8.0）：对非索引列也能改善选择性估计
ANALYZE TABLE t_idx UPDATE HISTOGRAM ON c WITH 32 BUCKETS;
SELECT * FROM information_schema.COLUMN_STATISTICS
WHERE TABLE_NAME = 't_idx';
```

## 4. Fast Index Creation 与 Online DDL（约 p.213–220）

**要点**：

- **Fast Index Creation**（InnoDB 插件时代引入）：建/删二级索引时可避免整表拷贝（相对旧拷表方式）。
- **Online DDL**：允许 DDL 期间 DML；用临时日志记录变更，受 **`innodb_online_alter_log_max_size`** 限制，日志满则失败。

**原文**：

> Fast Index Creation 可以避免创建索引时的表拷贝。Online DDL 允许在创建索引时对表进行读写，相关变更写入 online alter 日志；日志大小由 `innodb_online_alter_log_max_size` 控制。

**8.0.34 新写法**：

```sql
SHOW VARIABLES LIKE 'innodb_online_alter_log_max_size';

-- Online 加索引；支持时可用 INPLACE / INSTANT
ALTER TABLE t_idx ADD INDEX idx_bc (b, c), ALGORITHM=INPLACE, LOCK=NONE;

-- 部分变更可 Instant（几乎只改元数据）
ALTER TABLE t_idx ADD COLUMN d INT NULL, ALGORITHM=INSTANT;
```

## 5. 联合索引、覆盖索引与优化器提示（约 p.221–235）

**要点**：

- **联合索引**：按定义列顺序排序；可服务最左前缀、部分 `ORDER BY`。
- **覆盖索引**：查询列全在二级索引中，`Extra` 常现 `Using index`，无需回表。
- **`FORCE INDEX`**：强制指定索引（书中示例）；滥用可能掩盖统计问题。
- **MRR**（Multi-Range Read）：按主键排序后批量回表，减少随机 I/O。
- **ICP**（Index Condition Pushdown）：`Extra` 出现 **`Using index condition`**，在引擎层用索引条件先过滤。

**原文**：

> 联合索引按多列排序，可避免额外 filesort。覆盖索引使查询只访问索引即可。MRR 优化将随机 I/O 转为更顺序的访问；ICP 将部分 WHERE 条件下推到存储引擎，Extra 中可见 Using index condition。

**8.0.34 新写法**：

```sql
-- 覆盖索引
EXPLAIN FORMAT=TREE
SELECT a, b FROM t_idx WHERE a = 1;

-- Optimizer Hints（优先于旧 USE/FORCE INDEX 风格）
EXPLAIN FORMAT=TREE
SELECT /*+ INDEX(t_idx idx_ab) */ * FROM t_idx WHERE a = 1 AND b = 2;

SELECT /*+ NO_INDEX(t_idx idx_c) */ * FROM t_idx WHERE c = 'x';

-- MRR / ICP 相关开关（按需）
SET SESSION optimizer_switch = 'mrr=on,mrr_cost_based=on,index_condition_pushdown=on';
```

## 6. 自适应哈希索引（AHI）（约 p.236–240）

**要点**：

- InnoDB 对热点页自动建**内存哈希**，加速等值查找；对用户透明。
- 可用 `innodb_adaptive_hash_index` 开关；并非所有负载都受益（高并发争用时可能关闭）。

**原文**：

> InnoDB 存储引擎会监控对索引页的查询，若发现热点，则自动建立自适应哈希索引（AHI），使等值查询可走哈希查找。

**8.0.34 新写法**：

```sql
SHOW VARIABLES LIKE 'innodb_adaptive_hash_index';
SHOW STATUS LIKE 'Innodb_adaptive_hash%';
```

## 7. 全文检索（约 p.241–248）

**要点**：

- InnoDB 全文基于**倒排索引**（词 → 文档列表）。
- **FTS 限制**：中日韩等无天然空格界定符时分词困难；停用词、最小 token 长度等影响召回。
- 书中示例偏拉丁语系；中文场景需谨慎评估。

**原文**：

> 全文检索通过倒排索引实现。对于中文、日文、韩文等没有分隔符的语言，InnoDB 全文索引存在天然限制。

**8.0.34 新写法**：

```sql
-- 中文可用 ngram parser（仍不如专用搜索引擎）
CREATE TABLE t_fts (
  id INT PRIMARY KEY,
  title VARCHAR(200),
  FULLTEXT INDEX ft_title (title) WITH PARSER ngram
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

SELECT * FROM t_fts
WHERE MATCH(title) AGAINST('数据库' IN NATURAL LANGUAGE MODE);

-- FTS 辅助表（INFORMATION_SCHEMA）
SELECT * FROM information_schema.INNODB_FT_CONFIG;
-- 另有 INNODB_FT_DEFAULT_STOPWORD / INNODB_FT_INDEX_TABLE 等
```

## 8. MySQL 8.0.34 索引新能力速查

| 能力 | 说明 |
|------|------|
| 降序索引 | `KEY (a DESC, b ASC)` 真正降序存储 |
| 不可见索引 | `INVISIBLE`：优化器默认不用，可灰度下线 |
| 函数/表达式索引 | 对表达式建索引 |
| `EXPLAIN FORMAT=TREE` / `EXPLAIN ANALYZE` | 计划树与实际执行 |
| 直方图 | `ANALYZE TABLE ... UPDATE HISTOGRAM` |
| Optimizer Hints | `/*+ ... */` |

**8.0.34 新写法**：

```sql
ALTER TABLE t_idx ADD INDEX idx_a_desc (a DESC), ALGORITHM=INPLACE, LOCK=NONE;

ALTER TABLE t_idx ALTER INDEX idx_c INVISIBLE;
ALTER TABLE t_idx ALTER INDEX idx_c VISIBLE;

ALTER TABLE t_idx ADD INDEX idx_c_upper ((UPPER(c)));
```

## 9. 本章小结

1. **B+ 树**：balance；先定位页再内存查找；高度决定 I/O。  
2. **聚集 vs 辅助**：书签是主键；主键宜短。  
3. **Cardinality**：靠 `ANALYZE TABLE`；8.0 另有直方图。  
4. **DDL**：FIC / Online / Instant 演进；关注 online alter 日志上限。  
5. **访问优化**：联合/覆盖、MRR、ICP；Hints 用 `/*+ */`。  
6. **AHI / FTS**：AHI 透明加速；全文对中文仍弱，可用 ngram 或外挂搜索。
